# Releasing a new document

The document is generated by the verification platform's own test suite — nothing in this
repository produces or edits it. Publishing a new document means copying a generated artefact in
and recording which API version it describes.

1. **Generate the document** in the platform repository, on the release branch:

   ```bash
   bin/verification_api_openapi   # writes ./verification_api.json
   ```

   The script refuses to write anything unless the whole rswag suite passes, so a document only
   exists if every documented request and response was verified against the live endpoints.

2. **Copy it in and derive the YAML** from that same file, so the two formats cannot drift:

   ```bash
   cp /path/to/verification_api.json openapi/verification_api.json
   ruby -rjson -ryaml -e 'File.write("openapi/verification_api.yaml", YAML.dump(JSON.parse(File.read("openapi/verification_api.json")), line_width: -1))'
   ```

3. **Record the version** — copy `info.version` from the document into `VERSION`:

   ```bash
   ruby -rjson -e 'puts JSON.parse(File.read("openapi/verification_api.json")).dig("info", "version")' > VERSION
   ```

4. **Commit and push:**

   ```bash
   git commit -am "DIDWW Verification API $(cat VERSION), <what changed>"
   git push origin main
   ```

   `openapi/` only ever holds the current document; earlier documents stay reachable through the
   repository history.

CI lints the document and checks that the two formats agree and that `VERSION` matches
`info.version`. It cannot tell whether the document is up to date with the API: that is what the
generating suite is for.
